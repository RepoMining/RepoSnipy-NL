# RepoSnipy-NL v1.0.0

RepoSnipy-NL adds natural-language repository retrieval to the RepoSnipy
ecosystem while preserving the existing repository-to-repository workflow.

## Highlights

- One search box accepts `owner/repo`, GitHub URLs, or a software requirement.
- Requirements are encoded once with RepoSim4Py and projected into the stored
  README and docstring channel spaces.
- Coverage-aware fusion uses README `0.33` and docstring `0.67`.
- FastAPI service and Vue 3 interface are included.
- One frozen bilingual benchmark with 40 intents, 80 queries, and 2,706
  query-repository judgments is included.
- All 101 fusion-weight points are independently reproduced by the audit.

## Benchmark summary

| Split | nDCG@10 | strict MRR@10 | strict Hit@10 | strict P@10 |
| --- | ---: | ---: | ---: | ---: |
| Validation (20 queries) | 0.604229 | 0.458532 | 0.700000 | 0.150000 |
| Test (20 queries) | 0.659644 | 0.629444 | 0.900000 | 0.205000 |

These are closed-pool reranking results over the benchmark candidate union. They
do not measure full-index recall.

## Release assets

- `index.bin`: pinned upstream RepoSim4Py-compatible vector index;
- `index.bin.sha256`: checksum for the index;
- `reposnipy_nl-1.0.0-*.whl` and source distribution;
- `index_manifest.json`: pinned source commit, size, hash, and validated counts.

The index contains 9,678 unique repositories in the product dataset layout.

## Installation

Follow [docs/installation.md](../installation.md). Download the release index,
verify its checksum, and set `REPOSNIPY_DATASET=product`.

## Limitations

- The benchmark is a fixed candidate-pool reranking experiment.
- Online deployment requires model access and a writable cache.
- Natural-language retrieval quality depends on the stored README/docstring
  coverage of the index.
